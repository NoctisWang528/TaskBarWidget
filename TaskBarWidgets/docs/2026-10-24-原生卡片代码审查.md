## 发布验证额外发现

主分支既有更新回滚的 MediaPersonal 白名单遗漏 `lyrics/*.db-wal`、`*.db-shm`、`*.db-journal`。新程序健康失败后，数据库恢复但新建侧文件残留，已由隔离更新器用例复现。已将这三种侧文件纳入共同备份/日志校验/回滚白名单，并覆盖新增侧文件清除、原有侧文件恢复及相似名称文件保留。这不是本次 Harness 卡片迁移引入的问题。

## 对本次 Harness 产出的评价

模块分工基本合理：独立 STA、共享图形资源、纯数据模型和按需设置进程具备可继续维护的结构；大规模迁移和补齐模块的执行速度有价值。

运行正确性与验证选择明显不足。若干最基本的 Windows API 契约、坐标空间、请求封装及线程退出问题未被发现，而报告多次使用“已实现”“已验证”。已有测试主要验证原有媒体业务与设置模板，没有执行新增卡片的窗口、绘图和输入主路径。编译通过与旧测试全部通过不足以支持此次新前端可用。

“歌词非每帧全量重绘”应收窄表述：此实现仍以单张内容表面重绘媒体卡，尚未完成原方案中的静态/动态独立表面与全部文字布局复用。审查已减少隐藏定时器、无变化卡片重绘、整份快照的逐帧复制和图片重传；这不等于已经证明全部性能目标达成。

因此，本次产出适合作为需要资深审查的迁移初稿，不能作为无需审查即可发布的成品。评价只针对这些提交及其报告，不是对 DeepSeek V4.1 Flash 的通用基准；没有完整运行日志和成本数据，无法评价效率、价格或比较其他 Harness 的总体水平。
