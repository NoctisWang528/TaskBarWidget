# 卡片材质

“快捷卡片 → 卡片与顺序 → 卡片材质”提供液态玻璃、Mica、纯色。选择作用于五张普通卡片和独立更新卡，液态玻璃也用于卡片内菜单；设置窗口不受影响。

液态玻璃只显示一个“透明 — 模糊”滑块，范围 0–100%，默认 35%。浅色、深色共用这个值，背景染色、文字颜色和边缘反光自动跟随主题。滑块不改变文字或控件的不透明度。透明端保留轻微白色提亮和玻璃边缘，背景模糊半径为零；模糊端使用 24 DIP 标准差。高对比度或系统关闭透明效果时回退为纯色，原设置保留。

旧配置缺少材质字段时继续使用 Mica；Mica 的开关及四项历史参数保留，仅选择 Mica 时展开。选择其它材质不会覆盖这些参数。更改通过原有“应用更改”保存；卡片可预览当前草稿，离开材质页、重新读取或关闭设置会按原有草稿规则恢复已保存外观。设置窗口本身仍使用 Mica，玻璃效果在快捷卡片中查看。

## 绘制与平台适配

参考 [Kyant0/AndroidLiquidGlass](https://github.com/Kyant0/AndroidLiquidGlass/tree/eb4a0ea2e17542ea28c2e71088f7dd9acf77aad5) 的 `kmp` 分支：背景模糊、圆角距离场透镜、方向性边缘反光。参考仓库独立克隆在工作区旁，产品构建不引用外部路径。来源、修改记录与 Apache 2.0 全文见 [第三方许可](../licenses/Apache-2.0.txt)。

Windows Composition 不支持该仓库的 AGSL 任意像素着色器，也不支持 DisplacementMapEffect。实现采用实时捕获背景，在应用自己的 Direct2D 中完成逐像素位移，再把完成的图像交给 Composition。圆弧曲线与法线参考上游，Windows 适配不代表与 Android 示例或 Apple 材质逐像素一致。

- 支持会话排除列表时优先使用 Windows Graphics Capture（WGC）；否则沿用 Desktop Duplication 及其 WGC 后备。只在玻璃卡片显示期间采样所在显示器；Desktop Duplication 同 GPU 使用 GPU 复制，跨 GPU 使用两份暂存纹理和非阻塞读取。静止采样跟随卡片动画的目标帧率，跨 GPU Duplication 仍限制为 30 Hz；没有新桌面帧且几何／控件未改变时复用结果，不代表实测呈现帧率。普通关闭时停止采集并清除渲染器图像，WGC 保留分配用于复用；完整释放条件见下文，不保存截图文件。
- 捕获在呼出开始时启动，开合动画全程保持实时折射：同 GPU 的 Desktop Duplication 复用渲染设备，启动约 1 ms，首帧约一个刷新周期，此时卡片仍在屏幕外。跨 GPU 输出需要独立 D3D 设备（本机新建约 150–300 ms），首次创建不在动画中进行：该次呼出先用标准模糊，动画结束后创建并缓存，之后的开合直接复用。设备只保存无内容的 D3D 对象，捕获失败时释放。模糊值和主题改变保留健康的捕获会话。
- 开合期间每一帧先移动整组 HWND，紧接着按新位置渲染各卡玻璃，两者在卡片线程同一批 Composition 提交中送出；背景采样计时器在动画期间只做协调，不重复渲染。控件小透镜在动画中限制为约 30 Hz 更新，最后一帧和停止后补齐。HWND 位移与 Composition 内容不保证落在同一 DWM 帧，偶发一帧错位需真机观察。
- 收起动画保持捕获及相应的窗口排除；卡片完全移出屏幕后先停止捕获、恢复原捕获标记，再隐藏窗口，避免隐藏后修改标记留下空框残影。收起中重新呼出不重启捕获。卡片经过显示器底边时，背景采样按边缘像素延伸，不再向透明衰减。
- 圆角距离场使用 `1 - sqrt(1 - x*x)` 曲线，卡片透镜高度／位移量为 24／48 DIP；小尺寸限制透镜高度和位移。私有 Direct2D HLSL 透镜按内向位移采样，并进行七次光谱采样实现色散。Composition 接收完成后的普通 surface，不变换 backdrop，也没有零半径 backdrop 绕过路径。
- 输入先经颜色矩阵和高斯模糊，再进入 HLSL 透镜。颜色矩阵支持卡片 1.5 倍饱和度；不向范围为 0–1 的 Direct2D Saturation 属性传入 1.5。反光及提亮九宫格源画刷使用 `Fill`，私有整幅图像使用左上对齐的 `None`，避免源尺寸方框或纹理拉伸。
- 天气“小时／多日”共享一个胶囊底座，选择胶囊在两项之间移动。城市名称和来源链接不绘制普通按钮背景；鼠标操作不留下键盘焦点框。
- 滑块头缩小为 20×14 DIP，轨道为 4 DIP；按压放大幅度调整为约 22%。小按钮统一圆形，大按钮统一胶囊形。电量翻页按钮包含禁用状态的玻璃外观，禁用项仍不可操作。天气选中胶囊移动时增加独立的 280 ms 放大回弹。
- 控件位移输入来自应用私有的背景图像与轨道绘制，文字保持清晰；开关图标随滑块头移动，拖动保留原轨道坐标及抓取偏移。零宽度填充隐藏，不生成退化圆角裁剪。
- 流量热力图的每个日格（包括读取中的占位格）使用独立的小尺寸圆角玻璃透镜，复用现有背景图像、实时位移与色散，不增加捕获会话。流量等级色改为透镜上的半透明染色，移除固定高光及遮挡折射的实色填充；未来格降低透明度且不可点击，零流量使用边框，与未知数据区分。悬停、按下、选中和键盘焦点保留，高对比度及非玻璃材质沿用原有绘制。
- 背景与正文、媒体动态层分离，控件缓存按外观变化更新。减少动态效果时取消过渡，高对比度或系统关闭透明时使用原有纯色绘制。捕获／渲染失败时清空私有图像，恢复未变换的标准模糊；重试有次数和间隔限制。显示器旋转、负坐标及设备失效有明确转换和释放路径，硬件表现仍需验收。
- 开合动画时间从第一帧渲染起算，每帧最多前进 max(34 ms, 两个帧间隔)：同线程同步启动捕获等一次性开销只推迟动画，不会让首帧直接跳到终点。DDA 格式被拒的显示器会被记住，之后直接使用 WGC，WGC 失败时重新探测；日志记录每次捕获启动耗时。
- 呼出动画错过一帧的截止时间时立即安排下一帧，避免再多等一个帧间隔；消息队列有界处理，兼顾输入响应。尚未测量最终呈现帧率。

主要实现为 `Native/Cards/CardMaterial.*`、`CardRefraction.*`、`CardBackdropCapture.*`，采样生命周期由 CardHost 管理。协议使用稳定 ID `LiquidGlass`、`Mica`、`Solid`，另存 `CardGlassBlur`。将来新增材质时，扩展 ID 规范化、设置选项和原生材质分支即可；无需每张卡片单独实现，也不引入外部插件装载。

## 截图与录屏

优先对显示器 WGC 会话查询公开的 `IDisplayGraphicsCaptureSession`，将本进程卡片／菜单加入 `SetWindowExclusionList`。只有接口查询、列表设置和采集启动全部成功，才恢复这些 HWND 原有的 affinity：本程序的背景采集看不到被排除的窗口，其它截图／录屏可以正常包含它们。折射、色散、控件透镜和动画沿用现有渲染管线。

接口、列表设置或 WGC 启动不可用时，沿用原有采集路径和 `WDA_EXCLUDEFROMCAPTURE`，继续优先保证实时效果；此时遵循窗口标记的截图／录屏仍不包含玻璃卡片及菜单，可选择 Mica 或纯色录制。停止捕获或销毁窗口时恢复原来的 affinity。不改变其它应用窗口或系统捕获权限。

卡片内菜单保留原有行为：菜单打开期间，与菜单重叠的卡片暂时退出本程序的采集排除，其玻璃冻结，菜单因此折射真实的卡片内容。菜单关闭（开始淡出）时恢复排除，沿用两帧恢复等待。会话列表变化时优先更新运行中的 WGC 会话并排空旧帧，按系统相对时间过滤调用前的帧，等待两张调用后的新帧再刷新玻璃；失败时才重启采集。等待期间保留已完成的玻璃表面，不将返回的 `UInt64` 推定为帧同步保证，不新增菜单专用采集会话。旧路径中，冻结卡片暂时可被截图／录屏捕获，菜单本身仍全局排除。

使用的公开接口：[IDisplayGraphicsCaptureSession](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.idisplaygraphicscapturesession)、[SetWindowExclusionList](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.idisplaygraphicscapturesession.setwindowexclusionlist)、[Desktop Duplication](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api)、[Direct2D displacement map](https://learn.microsoft.com/en-us/windows/win32/direct2d/displacement-map)、[SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。固定 26100.0 SDK 缺少新接口头文件，局部 ABI 声明的 IID 和方法顺序已按系统元数据核对，不升级全局 SDK。两种排除方式均不可用时回退模糊，不启动会产生自身反馈的捕获路径。

启动诊断 `capture/wgc-session-exclusion` 表示会话列表已成功安装并启动；回退时保留 `session-exclusion unavailable at … hr=…`。这些状态写入现有 `card-backdrop.log`。本机独立探针在创建显示器捕获对象时返回 `0x80070005`，未到接口查询，不能据此宣称该系统已支持或不支持新路径；真实截图、录屏、阴影、HDR 和多显示器效果仍待验收。

## 2026-11-15 背景采样帧率

开合动画与静止背景采样共用目标帧率计算。设置为 0 时跟随显示器刷新率，未知时使用 60 FPS，范围为 30–240 FPS；静止采样使用背景所在显示器，跨 GPU Desktop Duplication 仍以 30 FPS 为上限。WGC 的最小更新间隔设为当前帧间隔的约 90%，帧率变化直接更新运行中的会话；旧系统不支持该属性时继续采集。

静止时控件透镜约每 16 ms 最多刷新一次，动画中的 33 ms 限制保留。没有新桌面帧时仍按节拍处理缓存背景，让最后一次控件变化得到补齐。静止轮询与渲染连续 30 次超过当前帧间隔时，有效采样率减半，最低 30 FPS，本次打开内不自动回升；重新打开或修改目标帧率设置后复位。动画帧率不受这一降频影响。

停止捕获时向现有日志追加一次汇总：目标及有效采样帧率、成功交付的新背景帧数、渲染帧数、静止 tick 数、平均及最大工作耗时（微秒）、工作超出帧间隔的 tick 数和渲染显卡描述。不记录屏幕内容、路径或用户数据，诊断离屏模式仍不写日志。

本次原生部分（含上述 C++ 改动）在 Release 配置下编译通过；完整 All/Release 构建在更新器步骤因构建环境找不到 `vswhere.exe` 中断，未产出完整包，也未运行探针。真实帧率与操作手感仍待用户验收。

## 2026-11-15 背景捕获资源复用与回收

在 2560×1440 显示器上进行一分钟、六次开合采样后，本进程专用 GPU 内存增长约 118 MB（每次约 20 MB），dwm.exe 私有内存增长约 174 MB（每次约 29 MB），随后等待 30 秒未见回落。单张该尺寸的 BGRA 图像约为 14.7 MB。尚未确认是哪一步未释放资源，D3D11 延迟销毁且未 Flush 是当前排查方向。

普通关闭卡片时，WGC 仅关闭会话并排空旧帧，保留捕获对象、双缓冲帧池、自有纹理和 D2D 位图。同一显示器、尺寸和渲染设备再次打开时，从保留的帧池创建新会话；创建失败则完整重建一次。停止后不向渲染器提供旧图像，排除窗口列表变化仍先停止旧会话、排空帧池，再启动新会话。

显示器、尺寸或渲染设备变化、捕获失败、离开液态玻璃材质、设备丢失、图形资源释放和退出时完整回收；按需资源模式沿用现有十分钟空闲释放入口，常驻模式保留复用资源。完整回收依次关闭会话和帧池、释放捕获对象与自有图像，再对 D3D11 即时上下文执行 ClearState 和 Flush；宿主随后清理共享 D2D 可回收资源并调用 DXGI Trim。Desktop Duplication 保留原有开合行为，销毁时也提交上述清理。

停止汇总增加本进程在渲染显卡本地显存段的当前用量（MB，不可用时为 0）和捕获资源保留／完整释放状态。原生部分在 Release 配置下编译通过，完整包未产出，也未运行验证；dwm.exe 是否停止随开合增长，仍待用户重新测量。

## 2026-11-16 输入线程、菜单捕获与渲染开销

用户提供的安装版记录：2560×1440、240 Hz、目标 240 FPS，展开约 36 秒，静止 tick 为 3474 次，平均工作 7596 微秒、最大 89162 微秒，1832 次超过帧间隔；约每秒渲染 97 次、采集 52 帧。菜单操作出现 capture/wgc-support、0x8001010D，随后重试并完整释放资源；用户观察到卡片打开时系统鼠标延迟，菜单附近接近停顿，打开菜单时整组卡片闪烁。84 个热图单元的独立透镜是开销嫌疑点，尚无分项测量结论。

原先 ShowCards 经 InstallHooks 在卡片 STA 线程安装鼠标和键盘低级钩子，鼠标按下还会直接进入 OnGlobalPointer、CloseMenu 和 ConfigureBackdrop。现将两种钩子移到单独消息线程，只读取事件并投递到卡片窗口，继续透传全部全局输入；移动只更新目标切换序号，不逐次投递，随下一条滚轮消息传递重置余量的信息；只读边界快照保留离开卡片又返回时清空滚轮余量的行为，也避免合并后的移动越过已排队的滚轮。隐藏和退出均停止并等待钩子线程。ConfigureBackdrop 遇到同步发送消息时改为投递后处理，避免在输入同步调用里启动或重启捕获。

菜单排除列表优先更新运行中的 WGC 会话，排空帧池，以系统相对时间过滤调用前的帧，等两张调用后采集的帧到达再交给渲染器；等待期间保留上一张玻璃。更新失败仍可重启捕获，有界重试等待时断开旧捕获输入，保留已完成的玻璃表面；重试耗尽仍回退，设备丢失或透镜自身绘制失败不保证保留旧画面。

停止汇总增加卡片玻璃与控件透镜各自的累计耗时、实际渲染次数和最近一轮刷新实际绘制的控件数；耗时是调用的工作时间，不是 GPU 时间戳。缓存补齐源位图身份、精确颜色和透镜依赖判断，只有焦点、启用状态或表层颜色变化时不再重做无关折射。热图保留逐格圆角、着色和交互，未来、零值、未知日期的区别沿用原实现；按压会改变各格的模糊及折射参数，本轮采用逐格透镜最多 30 Hz 的后备方案，没有合并为共享模糊通道。静止降频改为每 120 次 tick 中超过 30 次超时便减半，最低 30 FPS，重新打开和目标设置变化后复位。

上述修改随完整 All/Release 261116-1310 构建交付，构建与交付记录见 ACCEPTANCE.md。
