# 外设电量

实现约定：一个后台状态源供任务栏模块、原生卡片与 WinUI 设置使用。电量缺失不是零，充电状态可以未知，档位和估算保留原语义。设备身份不能使用名称或枚举序号。

## 内部接口

现有 current-user IPC 的 JSON 字段采用 camelCase。`getPeripheralBatteries` 返回 `PeripheralBatterySnapshot`；`refreshPeripheralBatteries` 合并刷新请求并立即返回当前快照；`subscribePeripheralBatteries` 接受 `{active:bool}`，为设置页提供临时采集需求，离页及连接关闭解除。设置页可每两秒读取内存快照，不执行硬件枚举。

卡片快照新增 `peripheralBattery`，格式同上。新增普通卡片 ID `peripheralBattery`；旧卡片 ID 与 Update 枚举值不变。卡片操作：`refreshPeripheralBatteries`；`setPeripheralBatteryMode` 接受 `{mode:"compact"|"detailed"}` 并通过正常保存回读。翻页为卡片本地状态。

Media 设置新增 `peripheralBattery` 对象：`mode`（默认 compact）、`hideDisconnected`（false）、`headsetControlEnabled`（false）、`vendorExtensionsEnabled`（false）、`order`（稳定 ID 数组）、`cardVisibility`（稳定 ID→bool）。卡片总开关继续使用 `quickCardEnabled.peripheralBattery`。

`PeripheralBatterySnapshot`：`version:1,revision,mode,hideDisconnected,refreshing,error,devices[]`。设备：`id,name,kind,connection,state,batteries[],updatedAt,stale,showInCard,canRead,source,compatibility`；电池：`role,percentage:int|null,levelText:string|null,estimated,charging:bool|null`。状态为 online/disconnected/sleeping/unavailable/unsupported。kind 为 mouse/keyboard/headset/earbuds/gamepad/pen/unknown。compatibility 为 verified/implemented/extension/identityOnly。

主程序接收 Media 命令 `peripheralBatteries`，其 `payload` 为完整快照。通过主线程更新动态内置显示项；item ID 为 `peripheral_<id>`，stable ID 自然为 `builtin_peripheral_<id>`。主程序发送 `peripheralBatteryDemand`，`payload:{deviceIds:[id...]}`，列出已加入任务栏的设备。连接重建时重新发布需求和完整快照。

原生采集程序 `TaskBarWidgets.PeripheralProbe.exe` 位于主程序旁，仅由 Media 服务启动。采用受父进程生命周期约束的匿名 stdin/stdout 管道，UTF-8 每行一个 JSON、最大 1 MiB。请求含 `version:1,requestId,operation,deviceIds,vendorExtensionsEnabled,attemptedInitializations,excludedIdentities`。回复含 `version,requestId,devices,initialized,error`。`progress` / `initialized` 事件均带 `version,requestId,identity`；初始化记录在写入设备之前发送，由 Media 保留至本次服务结束，子进程回收不清空记录。

`discover` 仅读取枚举/描述符；已确认的 HID++ 接收器随后通过 `identify` 查询配对单元身份。`read` 只访问请求的已发现身份。子设备须有协议提供的身份依据，不能以接收器槽位代替；休眠时保留之前确认的单元。规范身份优先采用序列号、蓝牙地址或容器及已证实的协议通道，由 `PeripheralIdentity.FromKey` 散列为公开 ID。无法区分的通道保持仅识别。串行请求，EOF 退出；监视父进程，不独立运行正常产品。

## 视觉与采集默认值

卡片宽 384 DIP：详细 288 DIP、每页四个；缩略 184 DIP、每页三个。无选中设备时不创建卡片。正常电量跟随主题，20%/10% 为仅视觉的低电量色阶；没有通知。读数变化与翻页不改变卡片尺寸。

活动任务栏/可见卡片每 60 秒读取，常驻隐藏卡片每五分钟读取；无需求停止主动读取。失败退避到十五分钟。单设备仅一个查询在途；协议限定的初始化次数和被动读取限制优先于调度。后台缓存只保存设备最近状态，配置与缓存不进入发行包。

标准 BLE 仅访问 `180F/2A19`，在已有连接和采集需求存续时订阅通知。支持读取时先获取一次初值；不支持通知时使用轮询，不调用 `MaintainConnection`。撤销需求、断连或退出时解除订阅。迟到的读取不能覆盖较新的通知。Windows 驱动取消若延迟完成，将保留原操作及其资源至清理完成，不并发替换；服务退出等待有界。

## 验收

兼容表按实际协议与证据记录，不将识别条目数量作为已验证型号数。软件测试不替代真实设备、Explorer、Mica 与混合 DPI 验收。构建和诊断不得启动日用程序、替换日用安装或修改启动注册。

交付同时附带 `peripheral-compatibility.csv` 与 `peripheral-compatibility.json`。可选 HeadsetControl 4.1.0 的独立程序、许可和对应源码位于 `Dependencies/HeadsetControl`，默认关闭。厂商扩展只连接已安装的服务；私有 HID 协议无需开启此选项。

DB179 的 262 条接收器记录、99 个协议标签已逐条登记：261 条有直接协议实现，Sony H5 一条使用可选 HeadsetControl；另列四条 O HUB 已安装驱动路径。这些数字是资料记录数，包含共享型号和重复身份，不是实机验证数量。仅在下文列出的实际连接上完成硬件读取；其余型号仍标记待验证。共享接收器须进一步匹配产品名、接口、报告和子设备身份；VGN 舟的 32/32/16 布局保持仅识别。MMX 230 的 GAIA 路径因缺少可靠型号与服务身份依据，仅识别，不发起 RFCOMM 查询。

标准 HID 仅接受描述符明确声明的百分比字段，支持 Feature/Input 报告及独立电池分量；没有角色依据时使用具名分量，不合并为整机电量。读取和可能阻塞的驱动调用在原生子进程中完成。

本轮已通过完整构建、142 项托管测试、协议离线测试、采集子进程契约测试、原生卡片回归、WinUI 发布模板及共享运行库检查。最终候选 `261110-1826` 补齐了更新器中新增程序和扩展文件的明确白名单。卡片覆盖 100%/125%/150%/175%/200% 的明暗、高对比度和减少动画渲染。Windows 拒绝离屏窗口的图形捕获，因此 SurfaceIsolation 不能计为通过；真实拖动、Mica、混合 DPI 与硬件充放电仍需桌面验收。按用户要求停止资源测量，不声明 CPU/内存目标已经达标。

## 2026-11-10 卡片交互修复

设备读数区域为只读文本，点击不发送卡片操作，也不改变其他卡片的启用状态。耳罩式耳机使用开放头梁与独立耳罩轮廓。分页采用短暂淡入和位移；详细／缩略切换由 CardHost 同步调整完整窗口高度及相邻卡片位置，内容只绘制目标尺寸，不在每一动画帧重绘。减少动画、高对比度及 DPI 变化时直接布局。

卡片显示连接方式和最近成功读取的本地时间；跨日读数包含日期。查询失败保留电量和成功读取时间，不展示“暂不可读”或内部异常类型。无成功读数的时间为“—”，诊断原因仍保留于服务快照。

Logitech 通过 HID++ 0005 读取实际设备名称，完成电量与硬件身份校验后才执行可选名称查询，失败不会丢弃已验证电量。实机返回 G502 X LIGHTSPEED、25%、未充电；同一稳定子设备身份重新发现或休眠时保留已获取名称，不按接收器 PID 猜型号。完整睡眠／唤醒周期仍未验收。
