# 卡片材质

“快捷卡片 → 卡片与顺序 → 卡片材质”提供液态玻璃、Mica、纯色。选择作用于五张普通卡片和独立更新卡，液态玻璃也用于卡片内菜单；设置窗口不受影响。

液态玻璃只显示一个“透明 — 模糊”滑块，范围 0–100%，默认 35%。浅色、深色共用这个值，背景染色、文字颜色和边缘反光自动跟随主题。滑块不改变文字或控件的不透明度。透明端保留轻微白色提亮和玻璃边缘，背景模糊半径为零；模糊端使用 24 DIP 标准差。高对比度或系统关闭透明效果时回退为纯色，原设置保留。

旧配置缺少材质字段时继续使用 Mica；Mica 的开关及四项历史参数保留，仅选择 Mica 时展开。选择其它材质不会覆盖这些参数。更改通过原有“应用更改”保存；卡片可预览当前草稿，离开材质页、重新读取或关闭设置会按原有草稿规则恢复已保存外观。设置窗口本身仍使用 Mica，玻璃效果在快捷卡片中查看。

## 绘制与平台适配

参考 [Kyant0/AndroidLiquidGlass](https://github.com/Kyant0/AndroidLiquidGlass/tree/eb4a0ea2e17542ea28c2e71088f7dd9acf77aad5) 的 `kmp` 分支：背景模糊、圆角距离场透镜、方向性边缘反光。参考仓库独立克隆在工作区旁，产品构建不引用外部路径。来源与修改记录见 [第三方声明](../licenses/AndroidLiquidGlass-NOTICE.md)。

Windows Composition 不支持该仓库的 AGSL 任意像素着色器，也不支持 DisplacementMapEffect。实现采用实时捕获背景，在应用自己的 Direct2D 中完成逐像素位移，再把完成的图像交给 Composition。圆弧曲线与法线参考上游，Windows 适配不代表与 Android 示例或 Apple 材质逐像素一致。

- Desktop Duplication 只在玻璃卡片显示期间采样所在显示器，同 GPU 使用 GPU 复制，跨 GPU 使用两份暂存纹理和非阻塞读取。采样目标为同 GPU 60 Hz、跨 GPU 30 Hz；没有新桌面帧且几何／控件未改变时复用结果，不代表实测呈现帧率。关闭后释放捕获和私有图像，不保存截图文件。
- 捕获在呼出开始时启动，开合动画全程保持实时折射：同 GPU 的 Desktop Duplication 复用渲染设备，启动约 1 ms，首帧约一个刷新周期，此时卡片仍在屏幕外。跨 GPU 输出需要独立 D3D 设备（本机新建约 150–300 ms），首次创建不在动画中进行：该次呼出先用标准模糊，动画结束后创建并缓存，之后的开合直接复用。设备只保存无内容的 D3D 对象，捕获失败时释放。模糊值和主题改变保留健康的捕获会话。
- 开合期间每一帧先移动整组 HWND，紧接着按新位置渲染各卡玻璃，两者在卡片线程同一批 Composition 提交中送出；常规 60 Hz 采样计时器在动画期间只做协调，不重复渲染。控件小透镜在动画中限制为约 30 Hz 更新，最后一帧和停止后补齐。HWND 位移与 Composition 内容不保证落在同一 DWM 帧，偶发一帧错位需真机观察。
- 收起动画保持捕获和窗口截图排除；卡片完全移出屏幕后先停止捕获、恢复原捕获标记，再隐藏窗口，避免隐藏后修改标记留下空框残影。收起中重新呼出不重启捕获。卡片经过显示器底边时，背景采样按边缘像素延伸，不再向透明衰减。
- 圆角距离场使用 `1 - sqrt(1 - x*x)` 曲线，卡片透镜高度／位移量为 24／48 DIP；小尺寸限制透镜高度和位移。私有 Direct2D HLSL 透镜按内向位移采样，并进行七次光谱采样实现色散。Composition 接收完成后的普通 surface，不变换 backdrop，也没有零半径 backdrop 绕过路径。
- 输入先经颜色矩阵和高斯模糊，再进入 HLSL 透镜。颜色矩阵支持卡片 1.5 倍饱和度；不向范围为 0–1 的 Direct2D Saturation 属性传入 1.5。反光及提亮九宫格源画刷使用 `Fill`，私有整幅图像使用左上对齐的 `None`，避免源尺寸方框或纹理拉伸。
- 天气“小时／多日”共享一个胶囊底座，选择胶囊在两项之间移动。城市名称和来源链接不绘制普通按钮背景；鼠标操作不留下键盘焦点框。
- 滑块头缩小为 20×14 DIP，轨道为 4 DIP；按压放大幅度调整为约 22%。小按钮统一圆形，大按钮统一胶囊形。电量翻页按钮包含禁用状态的玻璃外观，禁用项仍不可操作。天气选中胶囊移动时增加独立的 280 ms 放大回弹。
- 控件位移输入来自应用私有的背景图像与轨道绘制，文字保持清晰；开关图标随滑块头移动，拖动保留原轨道坐标及抓取偏移。零宽度填充隐藏，不生成退化圆角裁剪。
- 背景与正文、媒体动态层分离，控件缓存按外观变化更新。减少动态效果时取消过渡，高对比度或系统关闭透明时使用原有纯色绘制。捕获／渲染失败时清空私有图像，恢复未变换的标准模糊；重试有次数和间隔限制。显示器旋转、负坐标及设备失效有明确转换和释放路径，硬件表现仍需验收。
- 呼出动画错过一帧的截止时间时立即安排下一帧，避免再多等一个帧间隔；消息队列有界处理，兼顾输入响应。尚未测量最终呈现帧率。

主要实现为 `Native/Cards/CardMaterial.*`、`CardRefraction.*`、`CardBackdropCapture.*`，采样生命周期由 CardHost 管理。协议使用稳定 ID `LiquidGlass`、`Mica`、`Solid`，另存 `CardGlassBlur`。将来新增材质时，扩展 ID 规范化、设置选项和原生材质分支即可；无需每张卡片单独实现，也不引入外部插件装载。

## 截图与录屏限制

用户明确优先实时效果，接受无法兼顾时放弃卡片的截图显示。为避免卡片反复采到自身，实时玻璃的本进程卡片／菜单使用 `WDA_EXCLUDEFROMCAPTURE`：屏幕上可见，但遵循该标记的截图／录屏不会包含它们。切换材质、停止捕获或销毁窗口时恢复原来的 affinity。设置页同时说明这个限制；需要录制卡片时可选择 Mica 或纯色。不改变其它应用窗口，不隐藏整个程序的其它界面。

卡片内菜单例外：被排除的卡片对捕获不可见，菜单若照常采样会折射卡片背后的桌面，盖住卡片自身的文字和控件，看起来像不透明面板。菜单打开期间，与菜单重叠的卡片暂时取消排除，其玻璃冻结在打开前的一帧，菜单因此折射真实的卡片内容；这段时间该卡片会出现在截图／录屏中，菜单本身仍排除。菜单关闭（开始淡出）时立即恢复排除，卡片等待两张更新的捕获帧后再刷新玻璃，避免采到残留的自身图像。

使用的公开接口：[Desktop Duplication](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api)、[Direct2D displacement map](https://learn.microsoft.com/en-us/windows/win32/direct2d/displacement-map)、[SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。窗口捕获排除不可用时回退模糊，不启动会产生自身反馈的捕获路径。

## 验证范围与故障记录

本轮曾运行独立可见玻璃探针，随后出现多次 `dwm.exe / dwmcore.dll` 故障（`0x8000000B`），用户会话关闭并手动重启。探针与桌面共享 DWM，不能作为图形故障隔离。具体根因未证实；上述背景变换路径已移除，可见 `--glass-preview` 入口已停用。

按用户最新要求，本次修正只进行静态检查、完整 All/Release 构建与打包校验，不再运行可见探针、图形回归或桌面性能测试。现有测试源码同步到简化后的效果图，但不把未运行的检查记为通过。通过原有本地更新接口交付，真实外观、帧率、混合 DPI 和硬件稳定性由用户验收。

## 2026-11-15 回退与底色修正

安装后的 261115-0015 主程序哈希与交付包一致，更新日志为 complete。代码排查确认旧管线向 Saturation 传入越界的 1.5；按公开接口契约会被拒绝，当前异常路径随后停止全组实时折射并退回模糊。改用 ColorMatrix 保留 1.5 倍饱和度，控件使用恒等矩阵。此前没有持久诊断，不能据此断言用户机器上没有更早的捕获或渲染失败点。

移除固定 42% 深色／48% 浅色遮罩，统一改为很淡的白色提亮：深色 2.5%、浅色 6%。控件的采样边界外清为透明，避免填充黑底。透明材料的文字可读性依赖实际背景，外观仍由用户验收。

阶段变化和错误码写入 `%LOCALAPPDATA%/TaskBarWidgets/Logs/card-backdrop.log`，限约 64 KiB，仅含时间、PID、阶段、HRESULT、帧计数等运行状态；不写屏幕图像或媒体内容。诊断探针模式不写此日志。折射错误进一步区分效果创建、颜色矩阵、透镜绘制与 surface 上传等阶段。

本轮增加纯 CPU 的 FXC `ps_4_0 /O3` 编译验证，不创建设备或窗口、不执行着色器。它证明 HLSL 可编译，不证明捕获和最终硬件呈现成功。接口依据：[Saturation](https://learn.microsoft.com/en-us/windows/win32/direct2d/saturation)、[Color matrix](https://learn.microsoft.com/en-us/windows/win32/direct2d/color-matrix)。

0032 更新后用户展开卡片，持久日志确认更早的阻断：`capture start / 0x887A0004`，成功帧数始终为 0。因此饱和度越界并不是该机器最先触发的问题。为 DXGI 不支持的情况增加 Windows Graphics Capture 兼容后备，并保留后备前的失败阶段。WGC 将指定显示器捕获到渲染设备，使用两帧池和非阻塞轮询，关闭鼠标叠加，沿用窗口排除与私有透镜。会话、帧池与借用帧明确关闭；共享 D3D immediate context 开启多线程保护。首次三秒无帧视为失败并沿用有界重试。

WGC 不调用权限弹窗；系统未允许无边框捕获时仍可能显示捕获边框。当前使用 BGRA8 输出，HDR 色彩匹配及跨显卡呈现需要实际验收。DDA 保留为优先路径，未声明旋转时使用输出旋转／无旋转。接口依据：[WGC 显示器目标](https://learn.microsoft.com/en-us/windows/win32/api/windows.graphics.capture.interop/nf-windows-graphics-capture-interop-igraphicscaptureiteminterop-createformonitor)、[无 Dispatcher 的帧池](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.direct3d11captureframepool.createfreethreaded)、[系统捕获边框](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturesession.isborderrequired)。
