# 2026-10-22 保存阻塞与任务栏透明问题：根因分析与修复

> 本文接续 `docs/2026-10-22-任务栏透明与保存阻塞排查.md`（交接文档）。交接文档的证据大部分成立，但有三处关键结论被本次排查修正，见下文"对交接文档的修正"。

## 一句话结论

两个症状同源：**原生请求队列在第一次"重建窗口"的设置保存后停止排空**（唤醒标志残留），导致后续保存永久挂起，且所有外观/呈现更新冻结——"透明勾选后界面没变化/实色块"主要是冻结的旧外观帧。已修复 5 处（含 2af3b20 未覆盖的两个残留漏洞与一个内联重建自删隐患）。

## 对交接文档的修正

1. **"原生侧整体停摆直到进程重启"不精确**。10:36 现场（旧构建）显示队列在停摆约 49 秒后**自愈**：
   ```
   10:36:16 applyNativeSettings ok 28.4ms
   10:36:19 applyNativeSettings ok 41.2ms        ← 连续两次保存都成功
   10:36:40 applyNativeSettings TimeoutException 12002ms（10:36:28 发出）
   10:36:55 getNativeSettings   TimeoutException 12014ms
   10:37:07 getTrafficHistory   TimeoutException 12011ms
   10:37:17 weatherCommand ok  operationMs=10459.6（10:37:07 发出，随队列一起放行）
   native-media.log: 10:37:17 ×2 "Native settings rejected: Native settings request expired; retry the operation."
   ```
   请求**已入队**（否则不会在 10:37:17 被判 expired），是**排空（Tick）停了 49 秒**后被一次直接 Tick（如鼠标滚轮经过任务栏窗口，`Wheel()` 直调 `Tick()`）放行。没有此类事件时（11:10、11:40 现场）就只能重启。
2. **"Media helper launched + RecreateAll"不是窗口重建，是整进程重启**。native-media.log 中每次无前置 "Media pipe read failed." 的 helper 重启，都与 error.log 的 `CTaskBarDlgDrawCommonSupport::RecreateAll` 秒级对应（11:10:36、11:13:04、11:40:34、11:41:29…）；经进程取证，11:41:29 事件对应 `TaskBarWidgets.exe` StartTime=11:41:27——用户每次都是**重启产品**恢复的。窗口重建不杀 helper（见下）。
3. **helper/队列并不随窗口重建销毁**。`NativeMediaHost::Impl` 是进程级共享单例（`NativeMediaHost::Shared()`，NativeMediaHost.cpp:1308-1312；构造 :1314-1334 只是把 owner/wakeOwner 重绑到新窗口），管道线程、队列、辅助进程全部跨窗口存活。这正是唤醒标志可以"跨窗口残留"的前提。

## 根因一：保存阻塞（第二次保存永久挂起）

唤醒链：`EnqueueIncoming`（NativeMediaHost.cpp:282-296）→ `PostWake`（:220-243）→ `WM_MEDIA_HOST_WAKE` → `CTaskBarDlg::WindowProc`（TaskBarDlg.cpp:1254）→ `Tick`（NativeMediaHost.cpp:1072，入口先清 `uiWakePosted` 再 `ProcessIncoming`）。

**1102 构建（提交 1bdac39）的缺陷**：构造函数（当时无 `uiWakePosted=false; wakeWindow=nullptr;`，该两行由 2af3b20 添加）重绑新窗口后直接 `PostWake()`。当旧窗口销毁前有一条已投递未消费的唤醒（工作线程持续入队媒体消息，窗口重建窗口期极易命中），消息随旧窗口一起被丢弃而 `uiWakePosted` 停在 true → 此后所有 `PostWake` 空转 → 队列永不再排空 → 第二次 apply/getNativeSettings 全部挂起直到重启。第一次保存不受影响：它自己的唤醒就是处理它的那次 Tick（入口清标志），回复也经存活的共享 Impl 发出。

**2af3b20（HEAD）已覆盖主路径**（构造清标志 + wakeWindow 换窗重投 + HasIncoming 兜底定时器），但仍有两个残留漏洞，本次已补：

| 漏洞 | 修复 | 位置 |
| --- | --- | --- |
| 唤醒在 `m_media_host` 为空时被 WindowProc 吞掉（消费但不 Tick，标志卡死） | 回退到 `NativeMediaHost::TickShared()` 排空共享队列 | TaskBarDlg.cpp:1256-1263 |
| PostWake 不校验 owner 窗口存活（窗口死、标志不复位） | `IsWindow` 守卫，复位标志与 wakeWindow | NativeMediaHost.cpp:224-231 |

**结构性隐患（一并修复）**：设置应用同步执行在任务栏窗口自身的 WindowProc 栈上（唤醒→Tick→ProcessIncoming→bridge.Apply→ApplyUnifiedSettings），原实现内联 `CloseTaskBarWnd()` 会 `delete` 栈上仍在执行的 CTaskBarDlg 并销毁其 HWND（MFC 窗口过程自删）。现改为投递既有 `WM_REOPEN_TASKBAR_WND`（TrafficMonitorDlg.cpp:781-786，处理器 :2655-2660），重建移到消息循环，回复先于重建送达客户端。

## 根因二：透明不生效 / 实色块

**磁盘状态正确**：`task_bar_back_color = transparent_color = 1116946` ⇒ `IsTaskbarTransparent()` 为真（CommonData.cpp:173-179）。**渲染链路本身透明正确**：本机窗口 `ex=0x00210080`（NOREDIRECTIONBITMAP，DComp 逐像素 alpha，12:45 现场实测），交换链 `DXGI_ALPHA_MODE_PREMULTIPLIED`（TaskBarDlgDrawCommon.cpp:780），监测面背景 FillRect alpha=`透明?0:opacity`（TaskBarDlg.cpp:147-148），媒体卡底色经 NativeAppearance 覆盖为同规则（NativeMediaHost.cpp:265-271、:1023-1028 → MediaFrameContract.h:277 → NativeMediaPainter.cpp:369-370，alpha≈0 直接跳过）。

**但所有视觉状态更新都由 Tick 驱动**（`renderer.SetAppearance`、`taskbarAppearance` 命令、`SetMediaPresentation` 均在 Tick 内）。第一次保存触发窗口重建 → 队列停摆 → 之后外观/呈现状态机全部冻结，界面停留在保存前的帧（含不透明卡底/背景）——即"第一次保存成功但界面看不出变化（或变化不对）"和用户看到的实色块；重启后恢复。这与 2af3b20 提交说明的判断一致，且随根因一的修复一并解除。

**独立陈旧缺陷（已修复）**：`ApplyWindowTransparentColor()` 原在 `m_media_presented` 时整体提前返回（旧 TaskBarDlg.cpp:526）——媒体呈现期间保存设置，窗口透明样式永远不更新。现仅 GDI 色键分支等待（色键会把媒体面同色像素抠穿），alpha 渲染器分支照常应用；媒体面隐藏时补一次应用（`SetMediaPresentation`）。

**现场取证**（2026-10-22 12:22 截图）：QQ音乐正在播放时，监测窗口矩形（2,1112,320,1144）贡献零像素——两个表面都不可见（呈现状态机冻结/卡住的另一表现）。修复后需复测。

**遗留问题（待复测）**：media-settings.json 的 ShowBackground/BackgroundOpacity 与任务栏透明开关的交互（帧样式 surfaceColor 会被 NativeAppearance 覆盖，队列正常时不构成实色块，但建议真机复测媒体卡与监测面两种模式）。

## 本次代码修改清单

1. `Native/TrafficMonitor/NativeMediaHost.h:20`：新增 `static void TickShared();`。
2. `Native/TrafficMonitor/NativeMediaHost.cpp:224-231`：PostWake 增加 `IsWindow` 守卫，死窗复位唤醒标志。
3. `Native/TrafficMonitor/NativeMediaHost.cpp:1356-1362`：实现 TickShared（排空共享队列，与窗口绑定无关）。
4. `Native/TrafficMonitor/TaskBarDlg.cpp:1256-1263`：WM_MEDIA_HOST_WAKE 不再吞唤醒，无宿主时回退 TickShared。
5. `Native/TrafficMonitor/TaskBarDlg.cpp:524-532` + `SetMediaPresentation`：透明样式应用改为按渲染器分支跳过、媒体面隐藏时补应用。
6. `Native/TrafficMonitor/TrafficMonitorDlg.cpp:781-786`：窗口重建改投递 `WM_REOPEN_TASKBAR_WND`，不再内联自删。
