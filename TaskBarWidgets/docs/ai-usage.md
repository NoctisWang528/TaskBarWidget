# AI 用量

快捷卡片新增「AI 用量」，显示已打开服务的剩余额度、重置时间和最近 12 个自然周的每日活动热力图。可在「快捷卡片 → 卡片与顺序」中调整位置或关闭，在「AI 用量」设置页查看详细数据并刷新。所有服务关闭时不显示 AI 用量卡片，设置页仍可进入以打开服务。

设置中有 **ChatGPT、DeepSeek、Gemini、Claude** 四个独立显示开关，默认全部关闭。只有已打开服务的订阅／网页来源出现在列表与卡片切换中；「显示 API 用量」默认关闭，开启后也只显示已打开服务的 API 来源。关闭 API 显示时退回对应订阅来源；关闭当前服务时退回其他已打开的订阅来源，全部关闭后清空选择并停止采集。关闭服务或 API 显示均保留已有凭据和手动记录，重新开启后可继续使用。

ChatGPT 的订阅视图读取 **ChatGPT 账号下的 Codex**，它不代表 ChatGPT 网页聊天、语音、图像等功能的所有限制。

| 来源 | 自动读取 | 限制 |
| --- | --- | --- |
| ChatGPT（Codex 额度） | 官方客户端提供的额度窗口与每日 Token | 不涵盖全部 ChatGPT 功能限制 |
| ChatGPT API | OpenAI 组织 completions 的每日输入／输出 Token、本月组织费用 | 需要组织管理凭据；费用不等于可用余额，其他 API 产品的活动未合并 |
| DeepSeek API | 按 CNY／USD 显示官方余额 | 没有已确认的全账户每日 Token 接口，历史可手动记录 |
| Gemini API | Google Cloud 项目的输出 Token 历史、能够匹配的日请求配额 | 需要项目 ID 和有监控读取权限的服务账号 JSON；不包含输入 Token、每分钟等其他限制；监控存在延迟 |
| Claude API | 官方组织分析 API 的每日 Token | 需要组织管理／分析凭据；不代表个人订阅，也不提供可花费余额 |
| DeepSeek、Gemini、Claude 网页／订阅 | 尚无已确认接入的公开自动读取接口 | 提供官方入口及可选手动记录，手动值明确标记，不能伪装为实时官方数据 |

API 连接在本机设置页完成，不需要在聊天中粘贴密钥。凭据只写提交，验证成功后以 Windows 当前用户加密方式独立保存；留空保留已有凭据，清除操作明确执行。项目和来源偏好不含密钥。请求仅发送到各服务固定官方域名，禁止重定向和自定义地址；快照、日志及发行包不包含密钥。

全局“应用”保留 AI 页尚未提交的凭证、项目和手动记录输入，草稿只留在当前控件内存中。AI 写入进行时暂缓切页、普通关闭和更新安装；若设置连接中断，尚未完成的凭证验证会取消并保留原配置。

手动记录仅用于尚未接入自动历史的来源：订阅／网页按次数，DeepSeek API 按 Token。每天输入的是该日总量，保存时替换该来源的手动记录；没有填写的日期保持未知，可明确填写零。手动剩余百分比仅用于订阅／网页，和活动计数独立，不能相互推算；DeepSeek API 不接受手动百分比覆盖官方余额。查看或切换来源不会自动产生使用记录。

## 数据来源

通过本机已安装、已登录的官方 Codex 客户端启动短期 `codex app-server` 子进程，读取 `account/rateLimits/read` 和 `account/usage/read`。不创建模型任务、不使用额度重置机会、不购买积分，不读取或导出认证文件，也不扫描聊天正文。子进程采用重定向标准输入输出和隐藏窗口，退出时只清理本次创建的进程。

额度窗口按服务返回的时长显示，剩余百分比为 `100 - usedPercent`，限制在 0–100%。缺失窗口表示没有可用数据，不自动补成五小时或周额度，也不补零。重置时间来自服务时间戳，以本地时区显示。

Codex 热力图使用官方 `dailyUsageBuckets` 的日期和 Token 聚合，其他来源在页面标明其日期范围、单位与统计口径。OpenAI、Claude、Gemini 自动 API 历史按 UTC 日期排列并标注 UTC；手动记录按本地日期排列，避免把已有的 UTC 当日记录误标成未来。色阶按当前可见范围的最大日用量计算。无记录、明确零值、未来日期分别显示。数量采用 64 位整数；重复分页不能重复计数。Codex 累计用量使用服务的 `summary.lifetimeTokens`，可能不等于可见热力图之和；没有官方累计值的服务不把可见部分冒充全历史累计。

**Token 活动和订阅额度不是同一指标，不能相互换算。** 热力图帮助查看使用节奏；额度条表示账户对应窗口的剩余百分比。

## 生命周期与兼容

采集在后台进行，仅对已打开服务在查看或刷新时触发，并有缓存、最小刷新间隔和超时。未打开的服务不启动采集，关闭服务会取消其在途采集；全部关闭时设置页不轮询用量。读取失败显示可操作的状态；独立成功的额度读取不因历史接口不可用而被伪装成零。采集快照缓存在内存，连接配置与用户手动记录独立保存；读取时防止外部账号切换混合两人的数据。关闭产品会取消未完成的读取。

提供方采集与卡片展示分离，各来源有独立缓存、取消和凭据；发布版本号在切换来源时仍保持递增，旧回复不能覆盖新来源。卡片使用既有原生 Composition / Direct2D 架构，设置页继续使用 WinUI3。API 金额与百分比额度分开显示，未知余额不会补成零。

液态玻璃沿用当前原生卡片的共享材质与背景采样。热力图的非未来日期接入逐格折射：未知日期使用淡色，明确零值保留透明表面和边框，有用量的日期按色阶着色，未来日期留空。高对比度或玻璃不可用时使用普通绘制；日期格仍为只读说明，不增加点击行为。

## 验证与交付

本地诊断输出只包含额度与日聚合，不含凭据和聊天正文；诊断报告留在忽略的 `artifacts/`，不打入发行包。完整构建、解析测试、原生卡片测试、实际发布包设置模板检查通过后，使用现有本地更新接口交付。个人配置及历史由更新器保留和备份。

构建与回归结果见 [验收记录](../ACCEPTANCE.md)。离线协议、合成数据和离屏渲染检查不能替代真实账号、外设及桌面背景下的验收。
