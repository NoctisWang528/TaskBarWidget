# 单目录数据与双份本地包

产品只使用安装目录下的 `Data/`，不再读取或创建 `%APPDATA%/TaskBarWidgets/`，`global_cfg.ini` 也不再生成。原生主程序在加载设置、播种默认文件和启动媒体进程前，同步执行媒体程序的 `--migrate-data <安装目录>\Data` 阶段。媒体常驻进程仍通过 `--data-root <安装目录>\Data` 接收唯一数据根；目录不可写、布局损坏或包含链接时启动失败并提示权限问题，不会静默回退。

```text
Data/
  layout.json
  config/{app.ini,battery.ini,power.ini,weather.ini,media.json}
  history/{traffic.dat,traffic.dat.bak}
  lyrics/{user_data.db,song_maps.db,resolved-lyrics-v1.json,user-lyric-bindings-v1.json}
  cache/lyrics/{lyric-pipeline-raw-v1.json,lyric-pipeline-parsed-v1.json,smtc-generic-lyrics.json}
  secrets/weather-appkey.bin
  logs/{error.log,native-media.log}
  migration/{report.json,archive/}
  backups/{pre-restore-latest.zip,TaskBarWidgets-backup-*.zip}
```

`Data/layout.json` 记录布局 schema 与最近迁移。首次启动时，原生前置阶段在创建任何设置、数据库或缓存前扫描旧便携根目录、当前 `Data/database/` 和旧共享 AppData，按“目标新文件 > 当前安装旧数据 > AppData”合并；目标文件存在时绝不覆盖，旧文件原样归档到 `Data/migration/archive/<UTC时间>/`，只保留最近一次归档。JSON、INI、流量结构和 SQLite 完整性全部校验通过后才提交。复制、校验或提交失败会回滚本次目标并阻止启动，不写完成标记；已占用而暂时无法删除的旧文件会记录警告并保留，目标数据仍可用。

天气 AppKey 使用当前 Windows 用户的 DPAPI 加密存入 `secrets/weather-appkey.bin`，`weather.ini` 不包含密钥。密文不可跨用户或跨机器解密，迁移归档中可能仍有旧明文密钥，因此归档默认不进入备份或发布包，设置页会显示迁移警告。

出厂默认配置以资源形式编入程序，不作为包内文件发布：原生侧有 `Native/TrafficMonitor/defaults/config.default.ini` 与三个内置模块 INI，媒体侧有 `Media/Defaults/media-settings.default.json`。首次运行时只对**不存在**的目标文件逐字节写入，已有配置绝不被覆盖。删除对应的 `Data/config/*` 文件可重新得到该文件默认值。

先运行一次完整构建，再使用同一构建生成两份包：

```powershell
.\scripts\build.ps1
$personalSource = Read-Host '旧个人便携安装目录'
.\scripts\package-delivery.ps1 -PersonalSourceDirectory $personalSource
```

脚本默认读取 `artifacts/latest-build.txt`，也可用 `-BuildDirectory` 指定一个完整 Release 构建。它不启动产品、不注册自启、不替换旧安装，不自动重新构建产品。

输出为 `artifacts/deliveries/<构建版本>/`：

- `build/`：个人便携版，保留 `Data/` 下的新布局配置、流量历史、歌词数据和 DPAPI 密钥密文，排除缓存、日志、迁移归档与备份。天气密钥只能在创建它的 Windows 用户和机器上解密。复制整个 `build/` 即可携带其他个人数据。
- `release/`：从干净构建单独选择运行文件，提供干净目录、ZIP、SHA256。排除个人配置、历史、数据库、网页缓存、Cookie、日志、缓存和诊断图。保留第三方许可。

JSON 与流量文件在拒绝写入／删除的短读锁下复制，校验 JSON 或流量记录结构，再校验目标 SHA256。SQLite 使用既有 Microsoft.Data.Sqlite 的在线备份 API，能读取已提交的 WAL 数据，并对新库执行 `integrity_check`；不直接复制主库和侧车文件。任何失败都会停止打包，不覆盖源文件或已有交付目录。

`personal-data-manifest.json` 仅记录已复制数据的相对路径、方法与摘要。`release-manifest.json` 如实记录打包时工作区状态、基线提交与源码文件摘要；脏工作区不会宣称所有内容来自 HEAD，也不会生成虚假的远端提交链接。本地打包不提交、不推送、不发布 GitHub Release。

```powershell

$fixture = Join-Path $PWD ('artifacts/tests/sqlite-wal-' + [Guid]::NewGuid().ToString('N'))
dotnet run --project scripts/SqliteSnapshot/SqliteSnapshot.csproj -c Release -- --self-test $fixture
```
